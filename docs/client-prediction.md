# Client-side prediction и reconciliation

Клиент немедленно применяет собственный ввод с теми же MVP-константами, что и
сервер: 10 единиц за tick и те же границы арены. Каждый применённый input
сохраняется до подтверждения.

При получении snapshot клиент:

1. удаляет inputs до `last_acked_input_tick` включительно;
2. принимает авторитетную серверную позицию;
3. повторно применяет ещё не подтверждённые inputs;
4. плавно подтягивает отображаемую позицию к пересчитанной.

Inputs и snapshots передаются ненадёжными QUIC datagrams; номера тиков и
`last_acked_input_tick` позволяют переживать потерю/перестановку пакетов.
Prediction влияет только на отображение локального игрока. HP и результат
всегда берутся с сервера. Позиция противника хранится в snapshot-буфере и
рендерится на три server ticks позади; между соседними доступными snapshot она
линейно интерполируется. Старые и переставленные datagrams игнорируются.

Константы пока продублированы между Go и C++. Перед усложнением правил их нужно
перенести в общий versioned gameplay config или генерируемую схему.
