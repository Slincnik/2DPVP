# ADR-0002: QUIC-библиотека C++ клиента

- **Статус:** принято
- **Дата:** 2026-09-17

## Решение

Используем **MsQuic** для C++ клиента.

Причины:

- стабильный C API, который без проблем вызывается из C++;
- reliable streams и RFC QUIC datagrams в одной библиотеке;
- Linux и Windows, TLS 1.3, активная поддержка;
- сетевой callback API можно спрятать внутри `client/net`, не связывая с ним
  игровой цикл и raylib.

## Отвергнутая альтернатива

`quiche` подходит технически, но его публичный API ориентирован на C/Rust и
требует от приложения больше работы с UDP/event loop. Для маленькой команды
это лишняя инфраструктура по сравнению с MsQuic.

## Интеграция

MsQuic используется как официальная предсобранная зависимость, а не
`FetchContent`: его исходная сборка имеет собственные TLS-зависимости и
submodules. `make setup-msquic` скачивает закреплённый Debian-пакет 2.5.7 и
headers в игнорируемую Git директорию `.deps/`. `client/net` — единственное
место, где подключается `msquic.h`.
