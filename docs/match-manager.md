# In-memory MatchManager

Match Server больше не принимает общий development token. Оба клиента
предъявляют короткоживущие match tickets от Gateway.

1. первый валидный ticket для `matchId` ожидает второго участника;
2. второй ticket должен быть выписан на ожидаемого opponent;
3. создаётся одна общая авторитетная `Room`;
4. inputs обоих игроков поступают в одну goroutine комнаты;
5. каждый server tick один snapshot рассылается обоим игрокам;
6. `matchId` помечается использованным до истечения ticket.

Если потребитель snapshot отстаёт, старое состояние заменяется новым.
Авторитетная симуляция сеть не ожидает. Отключение участника отменяет room,
а ожидающий игрок удаляется при закрытии соединения.

Состояние пока локально одному Match Server. Горизонтальное масштабирование
потребует назначения конкретного сервера в Gateway и общего consumed-ticket
state или внутреннего RPC создания комнаты.
